# Physical send precondition (CNW #330 / prospective PN routing #139)

Message, image, file, video, audio, sticker, link, contact, location, poll and chat-presence requests accept optional JSON/form `expected_device_jid`. It must be an exact canonical PN JID, `digits@s.whatsapp.net` (1–20 digits); no whitespace normalization, AD device suffix, LID or slot UUID is accepted. Omission or the empty value preserves the existing send behavior. Global presence has no recipient and is outside this contract.

For a nonempty expectation the request must select an explicit device context. The selected instance and its client are captured once. Before preparing a send, before SDK media upload, and immediately before each SDK message send (including the existing 463 pre-warm/retry), the same instance must still own that captured client and `client.Store.ID.ToNonAD().String()` must exactly equal the expectation. A replacement client is rejected even if it reports the same PN JID. The provider never checks one selected client and then looks up another to send the message.

Invalid expectations return `SEND_ACCOUNT_INVALID` (422). Account/client mismatches return `SEND_ACCOUNT_MISMATCH` (409), with no message SDK send at the rejecting boundary. An earlier media upload or explicitly rejected 463 send may already have occurred before a later account check; this does not claim that no provider operation was attempted at all. Ordinary transport failures retain their existing unknown-outcome semantics.

A successful bound REST send returns `X-GoWA-Send-Contract: gowa-send-account-1` and `results.device_jid` equal to the supplied exact physical JID. This is provider account/send proof, not delivery or customer-seen proof. Consumers must require both fields and a separately qualified immutable deployment build before enabling this contract; an older deployment may ignore unknown request fields. Missing/mismatched success proof must remain unknown, never automatically resent under a new operation. No consumer qualification is granted by this code or documentation.

Focused synthetic gates, run from `src/`: `go test ./infrastructure/whatsapp -run 'TestPhysicalSendAccount|TestSendMessageWithReachoutRetry'`, `go test ./usecase -run 'TestSendTextRejectsWrongPhysicalAccount|TestMediaUploadRejectsReassignedSelectedClient|TestMediaSendEntrypointsRejectWrongPhysicalAccount'`, and `go test ./ui/rest -run TestPhysicalSendHTTPJSONAndFormContract`. They do not log in, send WhatsApp traffic, or claim deployment qualification.
